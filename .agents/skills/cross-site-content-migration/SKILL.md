# Migrate Cross-Site Content

1. Identify the authoritative source and destination applications or repositories and read their instructions, public documentation, release metadata, routes, and relevant source.
2. Classify material as public, internal, outdated, duplicated, personal, licensed, or uncertain. Do not publish internal material by default.
3. Reconcile names, versions, commands, URLs, compatibility, and deprecations.
4. Adapt content for the destination reader, preserve Sakura's voice where the source is personal, and link to canonical documentation for full procedures.
5. Replace source-only paths and instructions with destination routes or public URLs. Keep shared content in a package only when multiple applications need one maintained source.
6. Confirm asset provenance and licensing and preserve required attribution.
7. Mark genuinely uncertain behavior as unverified; never turn inference into fact.
8. Preserve route compatibility or report required redirects, canonical links, and reciprocal updates.
9. Follow the destination application's authoring, accessibility, and validation guidance.

Do not migrate secrets, private downloads, unpublished roadmaps, security-sensitive details, personal data, or internal-only content. Do not edit another repository or remote service unless it is explicitly in scope.
